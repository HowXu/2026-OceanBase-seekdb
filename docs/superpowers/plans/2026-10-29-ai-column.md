# Asynchronous AI Column Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在当前比赛分支实现题目全部异步 AI 列语义，并用五组原始 Mysqltest 及补充单测、故障回归验证。

**Architecture:** AI 结果使用物理列，定义和隐藏状态进入 Schema，任务随业务 DML 在同一事务中持久化。后台短事务领取/落盘结果，HTTP 调用不持锁，最终通过版本校验和单事务分组发布；RETRY、Strict Read 和向量写入复用同一内核规则及原生索引链路。

**Tech Stack:** C++17、OceanBase seekdb SQL/Schema/事务框架、CMake、GoogleTest、mysqltest、Python 3 确定性 Mock。

## Shared Interfaces

下列类型是最小接口契约。具体继承的内存管理和打印宏沿用所在模块惯例；不使用普通指针保存跨请求临时分配结果。

```cpp
enum class AIColumnState : int64_t { PENDING = 1, READY = 2, FAILED = 3 };

struct AIColumnTaskKey {
  uint64_t table_id_;
  uint64_t column_id_;
  common::ObString request_id_;
};

struct AIColumnClaim {
  common::ObString request_id_;
  uint64_t owner_id_;
  uint64_t lease_version_;
};

struct AIColumnOutcome {
  bool success_;
  common::ObString typed_result_;
  common::ObString failure_message_;
};
```

- 行维护入口：`int invalidate_rows(ObDMLRtCtx &, ObDMLTableChangeType, const ExprFixedArray &old_row, const ExprFixedArray &new_row)`；必须与调用方使用同一个事务。
- 执行入口：`int run_worker_batch(const int64_t max_groups, const ObCheckStopProvider &stop)`；不包含在事务中 sleep 或调用 HTTP 的实现。
- 发布入口：`int publish_group(const AIColumnTaskKey &, const AIColumnClaim &)`；不匹配返回使旧工作失效的可恢复状态，不写业务行。
- 严格检查入口：`int check_referenced_ai_columns(ObExecContext &, const ObIArray<TableColumnKey> &)`；每个 key 包含 `table_id` 与 `column_id`。
- 任务最终状态为 `PENDING / RUNNING / RETRY_WAIT / SUCCEEDED / FAILED`；RETRY_WAIT 的整数值固定为 `3`，匹配官方 worker 查询。AI 结果状态 `PENDING / READY / FAILED` 是另一套语义，不复用任务枚举。
- 字符串字段的 assign/set 接口深拷贝到所属对象的 allocator；发布前将结果转换成拥有独立生命周期的值，不能直接引用 SQL 结果迭代器的临时内存。

- [ ] **Step 1: 运行官方 worker 建立未消费任务的失败基线**

预期 INSERT 持续 PENDING 且任务残留。新增单元测试固定状态转换：

```cpp
TEST(AIColumnRetryTest, TwoRetriesAllowThreeAttempts) {
  TaskDecision d(2);
  EXPECT_EQ(TaskAction::CALL_MODEL, d.after_failure(0));
  EXPECT_EQ(TaskAction::CALL_MODEL, d.after_failure(1));
  EXPECT_EQ(TaskAction::MARK_FAILED, d.after_failure(2));
}

// 放在任务操作模块中，worker 和单元测试共用同一决策。
enum class TaskAction { CALL_MODEL, MARK_FAILED };
struct TaskDecision {
  explicit TaskDecision(int64_t max_retries) : max_retries_(max_retries) {}
  TaskAction after_failure(int64_t retry_count) const {
    return retry_count < max_retries_
        ? TaskAction::CALL_MODEL : TaskAction::MARK_FAILED;
  }
  int64_t max_retries_;
};
```

首次失败必须提交 `state=3,retry_count=1`，不能仅在内存重试直到成功。包括 HTTP 400 的模型任务级失败也进入此路径。

- [ ] **Step 2: 实现可恢复的任务操作**

每批以条件更新领取：仅 eligible 且未领取/租约过期的工作可成功，成功条件更新才拥有该 `owner_id, lease_version`。输出 claim 后结束事务。结果落盘及最终发布均把 claim、request_id、定义版本作为 UPDATE 条件。

同组其他列被新变更取代时，只让相应列的旧工作失效；不删除其他列，不让组永久等待。删除和同主键重插由新的 request_id 隔离。

- [ ] **Step 3: 实现模型调用、类型转换与有界生命周期**

从任务读取绑定的模型输入和配置，endpoint 名称/模型查找不能依赖业务正文。文本和向量通过已有模型协议，返回暂存到任务。JSON 完整解析、整数完整文本和溢出检查、字符串长度、向量维度和有限数值失败均为终态失败或按重试规则处理，不写部分结果。

`start` 启动有界线程；`stop` 停止领取；`wait` 等待在途任务；`destroy` 释放资源。HTTP 调用期间不得持有 SQL 事务或行锁。

- [ ] **Step 4: 实现分组终态发布与中断回归**

任务操作把同组终态结果在一个事务中更新业务结果/状态、原生索引，并删除任务。每次更新同时验证行 request_id、定义版本、claim。成功列 READY，最终失败列 FAILED，失败结果保持 NULL。

新增故障用例分别停止于领取后、单组结果落盘后和发布前。恢复不得重做已持久化成功结果；发布提交结果不确定时，以行上 request_id 和任务状态的幂等检查确定后续动作，不删除仍需要的工作。
