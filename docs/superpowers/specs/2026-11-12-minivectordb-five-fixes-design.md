# MiniVectorDB 五项正确性与存储修复设计

日期：2026-11-12
基线：`c4a54ebef06bf7ab5686b2c4866b53c658782b62`
行为参考：用户确认已通过正式正确性的 `b410e23ac01bcbf1df342faa6030034ab1d05e6c`

## 1. 目标与边界

修复五项已实测差异：

1. ORDER BY 序号被当作常量、无效序号错误成功。
2. 名称大小写、重复定义、表级主键、限定名和单表别名处理不足。
3. 向量数字词法过窄、float32 下溢被误报为溢出。
4. 无 AS 表达式的默认输出列名被重新拼接，丢失原始文本。
5. 小批 INSERT/UPDATE/DELETE 重写整表，RootStore 每次发布还扫描和同步所有旧对象。

继续使用 Python 负责 JSONL 与 SQLGlot 降级，C++ 负责执行、事务和存储。保留官方 JSONL 协议、精确向量扫描、CURRENT 原子发布和现有故障注入边界。

不增加 SELECT 1、SQL NULL、JOIN、聚合、子查询、OFFSET、DROP、ALTER、浮点标量或其他额外语句。不改变公开用例、配置、断言或协议，不复制参考实现的 Agent 材料。

本轮不提交、不推送。无需读取旧格式数据卷；新 Catalog/表格式只用于新数据目录。

## 2. SQL 表达式与名称解析

### 2.1 显示名称与查找名称分离

`ColumnSchema`、表项、索引描述符和显式别名保留输入的原始拼写。列、表、索引和别名的查找使用独立的 ASCII 小写规范化函数；只改变 A–Z，不做 Unicode 规范化或 locale 相关转换。

该规则同时用于：

- Catalog 的表名和向量索引名唯一性及查找；
- Schema 的列名唯一性及列查找；
- INSERT 列列表和 UPDATE 赋值的重复检测；
- SELECT/WHERE/ORDER BY/L2_DISTANCE 的列引用；
- CREATE VECTOR INDEX 的表列绑定；
- ORDER BY 的显式输出别名匹配。

`N BIGINT,n BIGINT` 必须报 `duplicate_column`。表和索引仅大小写不同也视为重复。

### 2.2 表级主键

CREATE TABLE 接受列内 `id BIGINT PRIMARY KEY` 和表级 `PRIMARY KEY(id)`。表级形式只能指定当前 Schema 中一个已声明的 BIGINT 列；未声明列、多列、重复主键或多个主键声明均拒绝。最终仍交给 C++ 同一个 `ColumnSchema.primary_key` 与 `validate_schema` 验证，不增加第二种运行时主键表示。

### 2.3 限定名、别名和括号

SELECT 的 FROM 允许一个单表别名。列引用可带限定名，但限定名必须匹配当前表原始名称或 FROM 别名的大小写规范化结果；匹配后才移除限定部分并绑定列。错误限定名报 `unknown_column`，不能直接忽略。

UPDATE/DELETE 的目标表列引用沿用同一单表名称绑定规则，但不新增 JOIN 或多表目标。

表达式外围括号递归剥离。WHERE 的比较、AND、L2_DISTANCE 参数等已有 AST 白名单仍然有效；括号不会使算术、OR、函数调用等新表达式获得支持。

## 3. ORDER BY 序号

ORDER BY 中不带正负号的十进制整数 token 降级为独立 `OrderPosition`，而不是普通整数 `Literal`。其他上下文中的整数仍是常量。

序号在 `*` 展开后的投影列表上按 1 开始绑定：

- `ORDER BY 1` 绑定第一个输出表达式；
- 允许绑定常量投影、L2_DISTANCE 投影和重复投影中的确定位置；
- `0`、大于输出列数、超出 uint64 的位置均返回语义错误；
- 空表和 `LIMIT 0` 之前同样完成位置检查；
- 带负号的数字不是序号，若现有表达式白名单不接受则明确拒绝，不能静默按常量排序。

名称排序键仍优先按输出别名匹配，采用大小写不敏感比较。多个同名输出只有在绑定表达式完全相同时才可共享；不同表达式继续报 `ambiguous_column`。序号直接指定位次，不经过别名歧义判断。

## 4. 默认输出列名

Python 前端为无 AS 的非 `*` 投影增加原始表达式文本字段。文本由原始 SQL 字符串及 SQLGlot token 的字符偏移切取，不根据 AST 重新格式化；别名节点被排除，只保留其实际表达式范围。

C++ 结果列名规则：

1. 显式 AS 使用别名原始拼写；
2. `*` 展开的每列使用 Schema 保存的原始列名；
3. 其他无别名表达式使用前端传来的原始表达式文本。

因此函数大小写、逗号后空格、外围括号及字符串内容不会因结果列名生成而改变。该字段只用于显示，不参与表达式等价性判断；排序表达式等价仍比较绑定后的结构。

原生 pybind 边界必须将显示文本作为带约束的 IR 字段验证，拒绝空字符串、NUL 和非法 UTF-8，不能信任任意 Python 调用方。

## 5. 向量数字与 float32 转换

所有 INSERT、UPDATE、精确距离和 ANN 距离继续共用 `parse_vector`。

单项数字语法接受可选 `+`/`-`，以及以下十进制形式：

```text
digits
digits.
digits.digits
.digits
```

以上形式均可带 `e`/`E`、可选指数符号和至少一个指数数字。`01` 合法；小数点两侧不能同时缺数字。向量仍要求方括号、逗号分隔、精确维度和完整消费输入。

转换分两阶段：

1. 将完整数字 token 转为 double；NaN/Inf 不由语法接受，转换产生非有限 double 时拒绝。
2. 将有限 double 转为 float32；结果必须为有限值。float32 上溢拒绝，有限值下溢为正零或负零允许。

double 下溢产生的零同样允许，因此 `1e-999` 可存成 float32 零。不能用一次 `from_chars<float>` 的 `result_out_of_range` 同时代表上溢和下溢。

拒绝项保持包括：NaN、Inf/Infinity、float32/double 上溢、维度错误、空向量用于正维度列、缺失数字、只有小数点或指数符号、尾随逗号、缺少逗号、额外右括号和其他尾随内容。负零下溢的符号按 IEEE 转换保留。

## 6. 基础段与增量段存储

### 6.1 Catalog 与文件布局

`TableEntry` 从单一 `object` 改为有序 `objects`：

- `objects[0]` 是按主键排序、无删除标记的基础段；
- 后续元素是按从旧到新的顺序排列的增量段；
- 新建空表仍拥有一个已完成的基础段，避免空列表成为特殊发布状态。

基础段沿用完整行排序编码。新增增量段格式包含独立 magic、Schema、按主键严格递增的记录以及 footer。每条记录包含主键、操作类型；PUT 携带完整新行，DELETE 只携带墓碑。一个语句产生的增量段中每个主键最多一条最终操作。

Catalog 升级版本并编码整个对象列表。引用校验、路径防逃逸和 Schema 校验覆盖每个段，不允许把 SQL 名称用于文件路径。

### 6.2 逻辑表读取

提供统一的逻辑表 reader，对基础段和增量段按主键归并：

1. 每个输入段先读当前最小主键；
2. 选择最小主键，同主键取最新段的操作；
3. PUT 输出完整行，DELETE 不输出；
4. 推进该主键涉及的所有输入，再处理下一主键。

SELECT、INSERT 冲突检查、UPDATE/DELETE 扫描、发布验证、恢复验证和合并压缩都使用该逻辑视图，避免不同路径对更新可见性的解释不一致。

段数阈值固定为 64 个增量段。若一次修改后超过 64 个，候选生成时把当前逻辑表与该语句变更一起合并为新基础段，并清空旧增量列表。阈值是同步、确定性的合并策略，不引入后台线程。恢复后不额外压缩，只有后续修改触发。

### 6.3 DML

INSERT 先绑定所有输入、检查批内重复，再流式读取逻辑表检测已存在主键；成功后仅写新增 PUT 记录。更新语句先验证所有赋值，再扫描逻辑表，仅对匹配行写完整 PUT；DELETE 对匹配主键写墓碑。无匹配行的 UPDATE/DELETE 复用当前对象列表，不创建空增量段，也不重写基础段；语句仍返回 affected_rows=0。

语句候选 Catalog 仅在完整段成功关闭后追加引用。异常时 OwnedObjects 清理未发布段；事务根继续保存未提交段，ROLLBACK 只丢弃候选根并由 GC 回收。

### 6.4 发布、恢复和 GC

RootStore 维护已经验证/同步的已提交对象集合。`publish(candidate)` 对候选中不在该集合内的对象执行完整读取验证与 fsync，旧基础段和旧增量段不再重复扫描、同步。外部排序临时文件不在候选 Catalog 中，因此不会进入该集合。

发布顺序不变：

```text
新段校验与 fsync
→ objects 目录 fsync
→ Catalog 写入与 fsync
→ catalogs 目录 fsync
→ staging CURRENT fsync
→ 原子 rename CURRENT
→ data 目录 fsync
→ ACK
```

`current_replaced` 之后的不确定性仍使实例 poisoned，禁止继续发布和 GC。recover 在 ready 前从 CURRENT 验证所有引用段，先同步 data 目录，再回收不可达候选。GC 必须保护 CURRENT、事务根和语句候选引用的每一个段，不能只保护基础段。

事务中每条语句只更新事务 Catalog；COMMIT 一次原子发布所有表的增量段，回滚和崩溃恢复语义保持原样。FlatScan 继续读取同一语句可见逻辑表，精确和 ANN 模式不需要维护第二份行状态。

### 存储与故障

- 基础段与多增量段的 PK 顺序、更新覆盖、删除墓碑、重插入和过滤 TopK。
