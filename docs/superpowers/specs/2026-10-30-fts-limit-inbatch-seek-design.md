# LIMIT/BMW 批内 doc-ID 定位设计

## 状态与授权边界

用户已确认“LIMIT 优先，先诊断跳距，再确定查找方案”的设计方向。本文将其细化为诊断和单候选实验；具体门槛随本文提交审阅。**本轮只写设计，未授权开始修改生产代码、编译或评测。** 文档审阅通过后编写实施计划，再按确认的执行范围推进。

C1 已撤回，C2 已取消，不恢复它们的生产改动。本设计不包含 C1b、doc-ID 浅引用、存储格式/解码优化或小 K 归并重写。

## 1. 目标和基线

目标是在不改变输出、评分、过滤及 BMW 语义的前提下，减少 `ObTextRetrievalDaaTTokenIter::advance_to()` 当前缓存批次内的大跨度线性比较。优化只能定位原逻辑已经允许推进到的位置，不能增加任何剪枝规则。

- 分支：`2026-competition-fts-clean-base`，当前文档 HEAD 为 `3e3233fab`，生产源码与保留 A+B 的 `964f20c92` 一致。
- 基线程序：`run_temp/fts-clean-base-final-seekdb`。
- SHA256：`6a97b9171f4774b8a7a460a734a59b5c7295e5ed1ec33858ee6714d567c0ca7c`。
- `build_release/src/observer/seekdb` 仍是此前取消的 C2 实验构建；不得冒充基线或最终程序。执行阶段须从当时实际源码重新构建、单独命名并核对身份。

证据见 `docs/superpowers/experiments/2026-10-30-fts-query-research-after-c1.md`。LIMIT 的 782 个 CPU 样本中，290 个含 token `advance_to()`，其中143 个含其 `get_next_row()` 子路径；106 个在 advance 栈下含已识别比较路径。集合可能重叠，unknown/inline 帧限制归因；37.08% inclusive 不是可兑现收益。

## 2. 必须保持的契约

当前搜索从 `cur_idx_` 开始，只向前，返回第一个满足原 `cmp_func_(target, cached_id) <= 0` 的槽位；若当前项已经满足，索引不动。

以下内容不变：

1. 继续使用初始化时选择的 doc-ID `null_first_cmp_`，保留原类型及 `CS_TYPE_BINARY` 比较规则；不改为裸 `memcmp` 或整数重解释。
2. `doc_id_` 仍为 `ObFixedArray<ObDocIdExt, ...>`，保存及输出仍深拷贝；不得恢复 C2。
3. doc-ID 与 relevance 使用同一槽位，不重排，不改 BM25 计算及浮点累加顺序。
4. 查不到时索引到达 `count_`，继续原 `token_iter_->advance_to(target)`、`get_next_row()` 和加载后首项检查；不直接绕过存储推进。
5. 保留原无效初始状态、比较器错误和 EOF 返回约定；不把错误转为未命中。新查找可能比较不同的槽位，但每次实际比较的错误均须向上传播。
6. `ObTextRetrievalBlockMaxIter` 的 ID 更新、shallow 状态切换，BMW 的 pivot、阈值、heap 和候选处理不变。
7. COUNT 不能省略评分，LIMIT 不能截断必要 posting；不增加依查询文本或数据集内容的特判。

## 3. 阶段 D：先诊断，不替换算法

### 3.1 先证明适用条件

在改算法前核对实际 LIMIT 执行计划和调用链，确认进入 BMW 及目标 token iterator。诊断记录与源码证明相结合：

- 当前批次按同一比较器非递减；不把数值业务主键顺序误当作内部字符串 doc-ID 顺序。
- 搜索范围内槽位均有效。追踪 token skip 的初始化、写入者及 eval_batch 参数契约，不能只凭采样中 skip 为零认定总为零。
- 部分批次、标量、重扫、advance 后加载的状态符合现有契约。

首版只考虑已证明条件下的向量批次，标量/单项和其他不能证明的状态保留原线性路径。不得为“保证有序”在正式版本每次重新排序或扫描校验整个批次。若需要运行时资格标记，应在已有批次保存循环中廉价维护；无法证明或低成本识别安全范围时停止本路线，而不是扩展为 skip/扫描语义修复项目。

### 3.2 诊断内容

临时插桩只累计整数统计，不改变原线性推进或结果，结束时统一输出；不逐项日志，不记录原始 doc-ID/文本，不使用全局原子热计数。

每次批内查找记录：

- 初始剩余长度 n；原线性执行的比较次数；首次满足项距起点的距离 d，耗尽记为 d=n。
- 跳距分桶：0、1、2–3、4–7、8–15、16–31、32–63、64 及以上。
- 当前即命中、批内命中、整批耗尽、调用存储推进、错误/EOF 的次数。
- 单项/标量回退次数、批长及有效性检查结果。

分桶只用于解释；算法选择使用逐调用的 n、d 计算整数比较次数模型，再累加，避免用分桶中点估算。模型仅回答比较次数，不测墙钟、不模拟 BM25，不重新比较或复制实际 doc-ID。

### 3.3 有限选择与停止条件

事先只比较两个方案，各用短线性前缀长度 1、2、4 的固定候选值：

- A：前缀失败后，对剩余范围做 lower_bound。
- B：前缀失败后，指数探测夹定范围，再 lower_bound。

前缀指最多执行的线性比较次数，包含当前项检查。模型应包含前缀、探测、二分及耗尽判断的全部比较，不只报告二分部分。模型须以简单排序序列穷举 n/d 的独立结果校验。

选择规则：

1. 若没有安全适用范围，或最佳模型相对原线性总比较次数减少不足 **20%**，停止，不创建生产候选。
2. 在通过上述条件的方案中，以总比较次数最少者为候选；若 A 的最佳值与全局最佳值之差不超过全局最佳值的 **5%**，优先选择较简单的 A。
3. 同方案多个前缀并列时选较短前缀。
4. 将所选方案、常量、诊断分布和选择计算写入记录后冻结，不在正式 A/B 结果出来后调参。

20% 是比较次数层面的筛选门槛，不是耗时收益预测。诊断运行使用原 benchmark 的不变配置，仅一次；不并行编译。若采集失败或不能确认实际路径，停止并报告，不静默重复。诊断耗时不参与性能验收。

## 4. 阶段 C3：仅实施一个被选中的查找

生产改动原则上限于 `src/storage/retrieval/ob_text_retrieval_token_iter.{h,cpp}`，只增加必要的私有查找逻辑/资格状态；能只改 cpp 就不扩展头文件。不引入通用搜索框架、运行时配置或两套备用优化。

实现采用明确的半开区间，维护“左侧已知小于 target、答案在尚未排除区间内”的不变量。相等应继续收紧左边界以取得第一个满足项，不能任取一个等值项。即使实际 posting 唯一，也测试等值情况。

- A：短线性失败后对剩余半开区间二分，结束索引可等于 `count_`。
- B：以剩余长度约束指数步进，先夹定答案区间再二分，不发生越界或整数溢出。
- 两者均不在搜索期间改变缓存、加载新批或重算分数；批内结果确定后才交回原外层流程。
- 检查 target 可能引用其他 iterator 缓存的情形，保持现有调用期所有权；不得引入跨批次裸引用。

未选择的算法不进入正式生产补丁。诊断计数、模型、额外校验和日志全部从正式候选移除。

## 5. 正确性验证

### 5.1 查找参考与边界

以原线性规则为 oracle，比对返回状态、索引、ID 及对应 score，而不只比命中数：

- target 小于/等于当前项，相邻项之间，等于末项，大于末项。
- 从非零索引开始、重复推进、等值项、长度 1、部分批、长批、边界处的探测/二分。
- 原先已耗尽、空批/EOF、跨批加载与重扫，保持现有支持/错误约定，不为测试扩展 API 合法状态。
- 比较器错误注入验证传播，不要求新旧算法访问相同槽位或在相同比较次数失败。
- 同一查找实现对受控有序数组做边界验证，并在诊断构建中与真实调用的线性参考对照。不得只测试脚本中另写的算法副本。

可用临时诊断校验代码验证上述内部状态；正式版本移除。永久行为回归放在现有 SQL 套件，若执行阶段发现必须新增 C++ 测试，则放 `unittest/storage/` 并明确可复现构建方式，不在 `tools/` 建测试文件。

### 5.2 SQL 与 golden

扩展 `unittest/storage/fts_query_batch_regression.sql/.result`，保持现有 2051 文档测试，并增加能驱动不同跨度的稠密/稀疏 token 分布、多个 LIMIT 值及跨批情形。覆盖中文/BEng/混合、多个 token、相关度阈值、同分次序、OFFSET、PREPARE 重用和 DML。

业务 ID 稀疏不等于内部 doc-ID 跳距大，必须由诊断确认用例确实触发相关路径。EXPLAIN/机制证据用于确认 BMW，不用“SQL 带 LIMIT”代替路径证明。

在修改生产算法前，使用固定 A+B 程序运行扩展测试两次，确认输出一致后冻结 golden。候选不得反向更新预期答案。完整对照有序 ID:score，不能只取 count 或任意摘要；现有 score 输出精度保持不变。

验收运行六组既有回归：BEng、Unicode、IK-chain、word-map、build-sort、query-batch。新测试仍接入现有 runner，不创建平行评分逻辑。

## 6. 单对 A/B 与建议保留门槛

诊断通过、算法冻结、回归通过并移除临时诊断后，最多执行 **一对完整 A/B**。每端原配置不变：

`ROWS=20000 BATCH=500 ROUNDS=3000 QUERY_ROUNDS=200 SAMPLES=3 WARMUP=30 SKIP_LOAD=0`。

A 为原 A+B 固定基线；B 为选中且不含诊断的 C3。编译最多 `-j11`，评测期间不编译、不挂 profiler，不修改 benchmark、评分脚本、历史 baseline 或输入规模，不执行 `telemetry_test.py`。

改善率定义为 `(baseline - candidate) / baseline`。建议同时满足以下条件才保留：

1. 六组正确性回归均与冻结预期一致，hits 仍为 8001 / 11000 / 7332 / 20。
2. `query_limit_avg_ms` 改善至少 **5%**。
3. 四条查询改善率算术均值 **不低于 0**。
4. 三条 COUNT 中每条改善率均 **不低于 -2%**。

完整报告九项结果、三类等权综合和原始三样本；构建/分词波动不能用于抵消查询门槛失败。出现无法解释的异常或测量条件失效时不宣称通过，不丢弃样本、不追加跑到过线，记录并撤回或暂停求助。
