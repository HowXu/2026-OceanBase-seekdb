## 2. 范围与不变量

必须实现：

1. `read_csv`、`read_json`、`read_ndjson`、`read_parquet`、`glob`，命名参数、表别名及动态列元数据。
2. CSV/JSONL 全量 Schema 推断，`sample_size` 仅支持 `-1`；七类推断类型及确定性宽化。
3. Parquet Footer Schema、多 Row Group、可空基础列、公开夹具所需编码与 Snappy、实际列裁剪。
4. 原生 SQL 表达式、过滤、排序、LIMIT、分组、HAVING、聚合，INNER/LEFT JOIN 及跨格式 JOIN。
5. `DESCRIBE SELECT * FROM read_*()` 的列结构输出，不执行数据查询，不以执行计划代替列元数据。
6. `COPY table-or-query TO path` 导出 CSV，支持表头、分隔符、引用、转义和 NULL 文本选项，能读回。
7. 默认关闭的 `enable_file_sql`、`secure_file_priv`、文件变化检测、有界资源使用和错误清理。

不实现远程文件、目录数据自动合并、嵌套 JSON/Parquet 结构、分布式文件扫描或外部 SQL 引擎代执行；不顺带迁移新版构建系统、存储重构或无关功能。

普通 SQL、原有 EXPLAIN/DESCRIBE 和 SELECT INTO OUTFILE 行为不得因新入口而改变。输入文件只读；只有显式 COPY 可以在授权目录内新建输出。

## 4. 执行架构与数据流

```text
SQL
  → Parser：文件函数/命名参数、DESCRIBE、COPY 入口
  → Resolver：功能与权限检查、全量 Schema 推断、动态列绑定
  → 原生优化器：文件扫描 + 普通过滤/聚合/排序/JOIN
  → CodeGen：源列序号与输出表达式的显式映射
  → 文件扫描算子：有界读取、批量产出、重扫、取消与变化检查
  → 普通 SQL 结果，或 COPY 输出算子
```

### Schema 与类型

Schema 推断只保留列名、类型、可空性、精度及必要的文件身份信息，不缓存全文件行数据。JSONL 字段按首次出现顺序形成并集，缺失值补 NULL，单行重名及嵌套结构明确报错。

类型集合为 BIGINT、DOUBLE、BOOLEAN、VARCHAR、DATE、DATETIME、NULL。NULL 不改变已有类型；BIGINT 与 DOUBLE 宽化为 DOUBLE；DATE 与 DATETIME 宽化为 DATETIME；其他不兼容类型宽化为 VARCHAR。整数溢出不得转为不精确整数；日期时间先验证合法性；保留支持范围内的小数秒精度。推断结果必须与 SQL 表达式和客户端元数据一致，不能只在辅助库中正确。

### 列映射、批量与重扫

代码生成必须同时携带“文件源列序号”和“目标表达式”，不能依赖全部 Schema 列与被引用表达式恰好一一对应。读取 `name`、重排列、同一列多次引用和 COUNT(*) 空投影均须正确。Parquet 仅解码需要的列；CSV/JSONL 仍验证记录结构，但不保留不需要的列值。

批量接口按执行器请求的容量产出，行与批量路径共享转换逻辑；每批检查取消/超时。重扫清空 EOF、批次和页内状态，重新验证文件身份，满足嵌套循环 JOIN 等重复读取需求。物理算子不持有超出批次有效期的临时字符串指针。

### DESCRIBE 与 COPY

DESCRIBE 读取已解析 SELECT 的输出列元数据。基础 `SELECT *` 必须符合公开六列结果；别名、投影与 JOIN 不得错误地返回第一个文件的全部原始列。优先直接构造结果表达式，不拼接未经正确引用的文件列名为可执行 SQL。普通 EXPLAIN 保留原生计划输出。

COPY 接入原生 SELECT 解析/优化/执行链路，以有界输出算子消费查询行；表名形式使用同一查询路径，不另写查询器。复用已有 select-into 机制中适用的逻辑，但将 COPY 的 CSV 选项及原子发布语义与原有 OUTFILE 明确区分。源列类型转文本后，按 CSV 规则处理 NULL、空串、引号及换行。

## 5. 安全、错误处理和资源

### 文件身份与路径

- 所有读取、glob、DESCRIBE 推断和 COPY 在访问文件前检查开关与当前 `secure_file_priv`，执行及重扫不能仅信任缓存计划中的旧权限值。
- 按现有 `secure_file_priv` 语义处理禁用值；不以空根目录回退到任意路径。
- 使用路径组件边界校验，拒绝 NUL、路径越界和符号链接逃逸。Linux 文件操作通过已验证目录句柄及防跟随链接的打开方式约束访问，不能仅 `realpath` 检查后按裸路径再次打开。
- 只读打开普通输入文件。以文件句柄检查设备号、inode、大小及高精度修改时间；在推断、扫描、重扫及 EOF 时比较身份，出现替换、截断或改写即报错，避免把旧 Schema 用于新内容。
- 缓存计划不得掩盖 Schema 变化；执行阶段验证不一致时明确失败，不能静默采用旧列定义。

### COPY 发布与清理

在已验证的输出父目录内以排他方式创建唯一临时文件，不使用进程计数器加可预测文件名后直接截断。查询成功、写入及关闭成功后，以“不覆盖已有目录项”的原子操作发布目标；不能用先检查存在再普通 rename 的方式实现禁止覆盖。

目标已存在（包括符号链接等目录项）必须失败。任何解析后执行错误、取消、写入失败或发布失败都关闭句柄并删除本次创建的临时文件；既有目标及输入不变。不增加超出赛题要求的断电持久性承诺。

### 资源与诊断

采用固定有界策略而非新增用户配置项：单条 CSV/JSONL 记录最多 16 MiB，最多 4096 列；单个 Parquet Footer、压缩页及解压页分别最多 64 MiB；glob 最多 100000 个结果。超限返回可定位的资源错误，不截断结果。以上为本实现的工程限制，不冒充题目规定值。

Parquet 长度、偏移、数量和乘法先检查文件边界、整数溢出及预算，再分配；按页推进，不物化完整文件或完整 Row Group 的数据。单个扫描器的动态工作区设 256 MiB 上限，涵盖其 Schema、记录、页、字典和批次等动态缓冲；与查询内存约束共同生效。错误清理不可依赖进程退出。

格式错误尽量提供路径、记录/物理行、列或 Parquet Row Group/页位置。辅助库异常在 SQL 边界转换为相应错误，内存不足、I/O 错误和取消不能穿出执行器或被改成成功。失败关闭文件、释放缓冲，重扫和 close 可安全收尾。

## 6. 分阶段交付与验收

| 阶段 | 改动范围 | 验证标准 |
| --- | --- | --- |
| 1. 迁移 | 仅功能文件和必要注册/构建适配 | 测试目标与服务端编译；比赛原始夹具未变；未混入新版无关改动 |
| 2. 扫描正确性 | 七类类型、列映射、批量、重扫、Parquet | 聚焦单测与端到端投影/COUNT/聚合；原始 Snappy 夹具可读；多 Row Group、可空列和裁剪可验证 |
| 3. SQL 补全 | DESCRIBE、COPY、JOIN | 元数据与实际结果一致；CSV 导出读回；INNER/LEFT 和跨格式 JOIN 使用 seekdb 原生计划 |
| 4. 安全稳定性 | 权限、文件身份、预算、清理、诊断 | 越界/符号链接/替换/并发目标创建被拒绝；坏行、资源超限、取消及导出失败无残留 |
| 5. 回归与证据 | 保持公开用例，增加专项回归 | 原版 file_sql mysqltest、扫描/Parser 单测及相关普通 SQL 回归通过；记录命令、结果和未验证范围 |

每个功能修正先补最小失败测试，再实现并运行；迁移阶段先建立当前缺失功能/无法编译的基线，不把静态检查视为执行验证。测试置于既有 unittest 或 mysqltest 目录，不新增独立 tools 测试程序。

重点验收矩阵：

- 语法：全部读取入口、命名参数及其类型错误、别名、glob、DESCRIBE、COPY 两种源。
- CSV/JSONL：BOM、UTF-8、LF/CRLF、字段内换行、转义、NULL 与被引用的 NULL 文本、坏行、字段并集、类型冲突与嵌套拒绝。
- 类型：整数边界、DOUBLE、布尔、合法/非法日期时间、宽化、小数秒和全 NULL 列；检查 SQL 端元数据与计算结果。
- Parquet：保留公开压缩夹具；增加多 Row Group、可空/字典/Snappy、畸形长度和裁剪测试；未支持编码明确失败。
- 执行：重排列、单列、COUNT(*)、WHERE/ORDER/LIMIT/GROUP/HAVING、INNER/LEFT、跨格式 JOIN、重复执行及重扫。
- 安全与导出：默认关闭、权限变化、越界与符号链接、推断后及扫描中文件变化、目录项替换、已有输出、并发发布、查询失败和临时文件清理。
- 普通 SQL：新关键字作为普通标识符的兼容行为、EXPLAIN、原有 DESCRIBE/OUTFILE；不为通过测试改变既有语义。

完成标准是可复现的构建与测试证据，不推断隐藏测试得分，也不在未运行时声称全量回归通过。
